## 7. 【要判断】設計上の論点

### 7-1. ユーザー名だけで他人の旅程に入れる

**`POST /login` はユーザー名のみ。**未登録なら作成、登録済みなら**同じ失効しないトークンをそのまま返す。**つまり**他人のユーザー名を打てばその人の会話・プロファイル・旅程がそのまま開く。**調査時点で 75 ユーザーが登録済み(`backend/app/domains/users/service.py:23-33`)。

> 「研究プロトタイプなので許容」とするかは**仕様判断**なので事実のみ記録する。許容するなら [10_requirements.md](10_requirements.md) に明記しておくのが望ましい。

### 7-2. 引数の 1 項目が不正なとき、手を丸ごと破棄してよいか

**未決。**[agent_planning_phase.md §23 論点 20](30_design/agent_planning_phase.md) に記録した。

現行は P3 / 事前条件が**手ごと破棄**する。実測では「**`自然` は実在するのに `山` のせいで推薦が 0 件**」「`mobility:"car"` のせいで推薦が 0 件」が起きた。§0.3 の語彙提示で発生頻度は下がったが、**外れたときに全滅する性質は残る。**

[ADR-0005](adr/0005-itinerary-solver.md) の「無言破棄の禁止」からすると、**不正な項目だけ落として実行し、落としたことを `unmodeled` で伝える**ほうが筋に見える。**ユーザーの判断を仰ぐ。**

### 7-3. ガードレールが手を破棄したあとのフォールバックが無い

§1-1 がこれである。**G5 が `ask_user` を破棄すると、代わりに何も起きない。**LLM は「聞きたい」と判断しているのに、選択肢の作り方が悪いだけで**質問そのものが消える。**

**2026-08-03: ユーザー判断により案 A を採用した。**

| 案 | 内容 |
| --- | --- |
| **A【採用】** | **guided decoding で `ask_user.args.options` に `minItems:2/maxItems:4` を課す。**旧来 `plan[].args` は `additionalProperties:true` で無制約だったので、**空の options を構造的に出せなくする**([understand_node.md §8](30_design/understand_node.md) の「形は保証する」に寄せる) |
| B | **プロンプトに `ask_user` の記入例を 1 つ足す。**現在 `例:` の節に `edit_itinerary` と `revert` の例はあるが、**`ask_user` の例が無い** |
| C | **G5 で破棄したら、コード側で既定の選択肢を補う。**ただし選択肢の中身をコードが作ることになる |
