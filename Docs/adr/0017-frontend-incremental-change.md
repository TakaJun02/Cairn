# ADR-0017: フロントエンドは差分改修に限る(全面リライト・NavView 分割をしない)

- 状態: **決定 (2026-08-01、ユーザー指示)。一部撤回 (2026-08-05)**
- ⚠ **[ADR-0023](0023-frontend-design-system.md) が「影響」節の「新規に足す UI は既存のスタイルに合わせる。新しいデザインシステムを導入しない」の 1 行を撤回した**(2026-08-05、ユーザー指示)。**それ以外の決定 —— `NavView.vue` の分割見送り、Service Worker の作り直し見送り、リファクタリング目的の変更の禁止、動いているモジュールへの不介入 —— は今も有効**である。表示層の作り直しの範囲は [30_design/frontend_design_system.md](../30_design/frontend_design_system.md) が正
- 日付: 2026-08-01
- 関係: **[20_architecture.md §10](../20_architecture.md) のフロントエンド節を一部撤回する**
- 設計: [30_design/frontend_nav.md](../30_design/frontend_nav.md) / [30_design/offline_field_mode.md](../30_design/offline_field_mode.md)

## 文脈(何が問題か)

[20_architecture.md §10](../20_architecture.md) は、フロントエンドについて次を挙げていた。

- `NavView.vue`(2,119 行)の分割
- Service Worker のタイルキャッシュの**作り直し**
- UI 文言の日本語統一
- 未使用コンポーネント・依存の整理

一方、**2026-08-01 にユーザーから明示的な指示があった**:

> フロントエンド UI は、現在の状態から変更しなくて良い部分は変更しないでください。変更や追加する必要がある部分(`ask_user` 用の入力欄など)があれば実装して OK です。

現行フロントは 6,621 行あり、**地図・音声再生・位置判定・LoRa シリアル通信は実機で動いている資産**である。バックエンドを作り直す本再設計と同時にフロントも作り直すと、**どちらの変更が壊したのか切り分けられなくなる。**

## 決定(何をすると決めたか)

**フロントエンドの変更は次の 2 種類だけに限る。**

| 変える | 例 |
| --- | --- |
| **新しいバックエンド契約に接続するために必要な差分** | SSE 対応、Bearer 認証、`GET /spots`、`state` イベント由来の UI(`ask_user` / `clarify` のチップ、旅程カード、パック生成の進捗)、LoRa ペイロードの decode |
| **実害のあるバグ** | Pinia 二重初期化、`marked` 出力の未サニタイズ、SW のタイルホスト不一致 |

**やらないこと(20 §10 から撤回する)**

- **`NavView.vue` の分割**
- Service Worker の作り直し(**URL パターンの修正にとどめる**)
- 動いているモジュール(`NavMap` / `audioManager` / `usePosition` / `geoutils` / `loraBridge` の AT コマンド部・`useNavWindow`)への手入れ
- リファクタリング目的の変更全般
- 未使用の残骸(`PlanView` / `PlanForm` / `counter.js` / `icons/*`)の削除 —— **消してもよいが優先しない**

## 理由(なぜ他案でなくこれか)

1. **切り分けの問題である。**バックエンドを全面的に作り直す期間にフロントも作り直すと、不具合の原因がどちらにあるか分からなくなる。**片側を固定するのが最も安いデバッグ戦略**である
2. **`NavView.vue` の正しい分割線は、オフライン動作を実機で通してからでないと引けない。**紙の上で分けると、実機で作り直すことになる
3. **本プロジェクトの主眼はバックエンド側にある**(推薦・プランニング・エージェント設計)。フロントの構造は成果に直結しない
4. **開発者は 1 人**(NFR-1 の前提)。時間配分として、動いている 6,621 行を書き直す価値が小さい

## 影響(この決定で生じる制約・やること)

- **[20_architecture.md §10](../20_architecture.md) のフロントエンド節を改訂する。**「NavView の分割」「SW の作り直し」を撤回し、差分の一覧([frontend_nav.md](../30_design/frontend_nav.md))へのポインタにする
- **Phase 4 の完了条件が変わる。**「NavView 分割」は完了条件から外れ、**オフラインで通しで動くこと**が条件になる
- **`22_current_issues.md` の指摘のうち、フロント側の一部は「見送り」として残る**(§13-1 の 2,119 行、§13-6 の localStorage 丸ごと永続化、§13-10 の残骸)。**見送りであることを明示する**のがこの ADR の役割で、忘れたわけではない
- **新規に足す UI は既存のスタイルに合わせる**(Tailwind + 既存コンポーネントの見た目)。新しいデザインシステムを導入しない
- この決定は**フロントエンドのみ**に適用される。バックエンドは従来どおり作り直す
