# ADR-0012: 知識検索を pgvector + Qwen3-Embedding-8B で行い、字句検索・全文取得・Web 検索を併置する

- 状態: **承認 (2026-08-01、ユーザー判断)**
- 日付: 2026-08-01
- 関係: **[ADR-0002](0002-single-postgres.md) の影響節を改訂する**(同 ADR が用意した「必要になったら pgvector を足す」の発動)/ [ADR-0011](0011-knowledge-search-subagent.md)(この 4 Tool を持つ主体)
- 設計: [30_design/narration_qa.md](../30_design/narration_qa.md)

## 文脈(何が問題か)

[ADR-0002](0002-single-postgres.md) は長期記憶のスコープ外化に伴い、ChromaDB と埋め込みサーバへの依存を削除すると決めた。その結果、**知識ベース(日本語 MD 118 本)を何で引くかが未定になった**([20_architecture.md §7](../20_architecture.md) の注記)。

2026-08-01、ユーザーから**埋め込みサーバは常時利用可能**であることが示された。実際に確認した(同日):

| | |
| --- | --- |
| エンドポイント | `.env` の `Embedding_server` — 応答あり |
| モデル | **`Qwen/Qwen3-Embedding-8B`** |
| 次元 | **4096**(実測) |
| `max_model_len` | 8192 |

あわせて `.env` に **`tavily_APIkey`** が追加された。

## 決定(何をすると決めたか)

**知識検索の Tool を 4 つ持つ。**主体は知識検索サブエージェント([ADR-0011](0011-knowledge-search-subagent.md))。

| Tool | 引数 | 中身 |
| --- | --- | --- |
| **`semantic_search`** | `{queries: string[] 1..3}` | **pgvector + Qwen3-Embedding-8B**(4096 次元) |
| **`lexical_search`** | `{keywords: string[] 1..6}` | **決定的な字句一致。**NFKC 正規化 + casefold。ヒットゼロなら**バリアント展開**して再試行 |
| **`get_document`** | `{doc_ids: string[] 1..2}` | **1 文書の全チャンクを `chunk_index` 順に取得。LLM 呼び出しゼロ** |
| **`web_search`** | `{queries: string[] 1..3}` | **Tavily。**ドメイン制限なし。サーキットブレーカーつき |

**ベクトルは同一 Postgres に pgvector 拡張で持つ。**新しいデータストアを増やさない。

**チャンクは `##` 見出し単位**(最大 ~500 トークン、オーバーラップ 50)。**埋め込み対象は `title + heading + 本文`。**

## 理由(なぜ他案でなくこれか)

### 1. ADR-0002 はこの場合を先に許可している

> "ベクトル検索が将来研究上必要になったら、**同一 DB に pgvector 拡張を追加して再導入する**(新しいデータストアは増やさない)"

**本件はこの発動であり、ADR-0002 の覆しではない。**直すのは影響節の 1 行(「`.env` の `Embedding_server` は削除対象」)だけである。

### 2. 意味検索だけでは足りない — 実データで確認した

日本語 MD 118 本を `##` で割ると、見出しが激しく重複する(実測 2026-08-01)。

| 見出し | 出現ファイル数 |
| --- | --- |
| `## 概要` | **115** |
| `## アクセス` | **58** |
| `## 見どころ・特徴` | 41 |

**ほぼ同型のチャンクが大量に競合する。**さらに「あがりこ大王」の `## アクセス` チャンクは本文中に「あがりこ大王」を 1 度も含まない(`**車**: 象潟IC から約15分…` だけ)。

- **`title + heading + 本文` を埋め込み・検索対象にする**ことで、この構造的な問題を解消する。**ナレッジ MD の全面書き直しは要らない** — こちらのデータは `title` が常にスポット名・テーマ名で、見出しが質問語彙(アクセス・見どころ・基本情報)に標準化されているため
- それでも**固有名詞・数値・施設名の完全一致には字句検索のほうが確実**である。埋め込みは意味の近さを測る道具であって、「spot_012」「象潟IC」が本当に含まれるかを保証しない

### 3. 全文取得が要る理由 — 断片では列挙系に答えられない

必要な情報の散らばり方は質問で変わる。「あがりこ大王の駐車場は」はヒット位置の前後で足りるが、「あがりこ大王について詳しく」は**ファイル全体**が要る。断片だけを返す設計は列挙系を原理的に拾えない。

**`get_document` は LLM を呼ばない。**全文を読むのは次の周回のサブエージェント自身である(追加の LLM 呼び出しゼロ、DB クエリ 1 回)。

### 4. 断片観測には `doc_id` と `truncated` を必ず載せる

**`doc_id` が観測に出ないと、サブエージェントは `get_document` を発行できない。**また断片は**ヒット位置中心 ±200 字**にする(先頭固定にしない) —— 先頭固定だと「肝心の箇所の手前で切れる → 途切れていると誤認して同義語で再検索する」空転が起きる。

### 5. 採らなかった案

| 案 | 不採用の理由 |
| --- | --- |
| `spot_id` → `md_slug` 直引きのみ | スポットに紐づかない質問(「クマは出ますか」「初心者向けの道は」)に答えられない。**テーマ横断が 58 本ある** |
| 全文検索(`pg_bigm` / `pgroonga`) | **日本語トークナイザが標準 Postgres に無い**ので、どのみち拡張が要る。pgvector と手間が同じで、語彙のずれに弱い。なお**字句検索は拡張なしで実装する**(§ Tool 表) |
| ベクトルを別ストア(Qdrant など)に置く | ADR-0002 の「新しいデータストアを増やさない」に反する。**118 文書に専用ストアは過剰** |
| ベクトルをプロセス内メモリだけに持つ | 状態の single source of truth は DB という原則(P4)。再起動のたびに 118 本を再埋め込みするのも無駄 |
| 埋め込みを使わず LLM にタイトル一覧から選ばせる | LLM 呼び出しが増える。サブエージェント化(ADR-0011)により、そもそも反復の中で選べる |

## 影響(この決定で生じる制約・やること)

- **[ADR-0002](0002-single-postgres.md) の影響節を改訂する。**「`.env` の `Embedding_server` と関連コードは削除対象」を取り消す。**ChromaDB と `chromadb`/`faiss-cpu` 依存の削除は維持**(データストアは増やさない)
- **Postgres イメージに pgvector 拡張を足す。**`postgis/postgis:16-3.4` を基に `postgresql-16-pgvector` を入れた派生イメージをビルドする(`50_operations/`)
- **`static` スキーマに知識テーブルを追加する**([30_design/data_model.md](../30_design/data_model.md)): `knowledge_documents` / `knowledge_chunks`(`embedding vector(4096)`)
- **`.env` に `tavily_APIkey` を追加**(追加済み)。`.env.example` にも説明つきで載せる
- **Qwen3-Embedding のクエリ側 instruct プレフィックスを必ず付ける。**文書側には付けない。**これは Qwen3-Embedding 固有の仕様で、付け忘れると精度が落ちる**
- **埋め込みサーバは別マシン依存である。**落ちていても DB のベクトルは残るので、**縮退するのは「質問文の埋め込み」だけ**。そのときは `lexical_search` に縮退し、明示する(NFR-5)
- シード時に 118 本を埋め込んで投入する。`python -m app.cli index-knowledge`(冪等)
- **孤児 MD の検証**(どこからも参照されない MD、参照先のない `md_slug`)を `validate-knowledge` で継続する
