# ADR-0023: フロントエンドにデザインシステムを導入し、表示層を作り直す

- 状態: **承認 (2026-08-05、ユーザー承認)**
- 日付: 2026-08-05
- 関係: **[ADR-0017](0017-frontend-incremental-change.md) の「新しいデザインシステムを導入しない」を撤回する**(ADR-0017 の他の制約は維持する)
- 設計: [30_design/frontend_design_system.md](../30_design/frontend_design_system.md)(本 ADR とセットの決定稿)
- 参考: [23_ux_issues.md §4](../23_ux_issues.md) / [25_known_issues.md](../25_known_issues.md)

## 文脈(何が問題か)

**2026-08-05、ユーザーから明示的な指示があった。**

> 今のフロントの UI デザインはかなりダサいので、カッコよく作り直してください。チャット画面の UI は下記のリポジトリの UI を参考に、かっこよくしてください。
> チャット画面内にウィンドウとして配置している、旅程計画を表示する画面も、見にくく使いにくい・デザインとしてもカッコよくない UI デザインになっているので、作り直してください。

一方 [ADR-0017](0017-frontend-incremental-change.md)(2026-08-01)は、フロントの変更を「バックエンド契約への接続」と「実害のあるバグ」の 2 種類に限り、影響の節で次を課していた。

> **新規に足す UI は既存のスタイルに合わせる**(Tailwind + 既存コンポーネントの見た目)。新しいデザインシステムを導入しない

**この 1 行が今回の指示と正面から衝突する。**[23_ux_issues.md §9-2](../23_ux_issues.md) も「§4-3(地図パネルの再設計)は ADR-0017 の制約と衝突する可能性があり、その場合は先に ADR を書き直して承認を得る」と予告していた。**本 ADR がその書き直しである。**

### 現物で確認した破綻(2026-08-05、`http://localhost:5173/` を 1440×900 で実機確認)

| 所見 | 対応する既知issue |
| --- | --- |
| **明暗が画面内で衝突している。**会話面は `gray-800` のダークなのに、入力ドックは `slate-50`、スターターカードは `white/80`。**1 画面に 2 つのテーマが同居している** | 新規 |

**ADR-0017 の判断は当時の文脈では正しかった。**バックエンドを全面的に作り直す期間にフロントも動かせば切り分けができなくなる、という理由だった。**その前提はもう成り立たない** —— ReAct 再構築([ADR-0019](0019-react-main-agent-subagents.md))は実装・レビュー・実機確認まで完了しており、バックエンドは動く状態で固定できる。**いま作り直すなら、切り分けの相手は固定されている側である。**

## 決定(何をすると決めたか)

**フロントエンドに 1 つのデザインシステム「Chokai Signal」を導入し、表示層を作り直す。**

### 1. デザインシステムを導入する(ADR-0017 の該当行を撤回)

トークン(色・角丸・影・モーション・書体)を 1 か所で定義し、全画面がそれだけを参照する。定義は [frontend_design_system.md](../30_design/frontend_design_system.md) が正。

**参考実装は [TakaJun02/sarutahiko](https://github.com/TakaJun02/sarutahiko)(APU-Navi)** —— ユーザー指定。**構造・余白・タイポグラフィ・モーションの設計は踏襲し、配色だけ鳥海山向けに色相を差し替える**(ユーザー判断 2026-08-05)。参考実装と別アプリだと一目で分かる状態にする。

### 2. 作り直す範囲は「表示層」に限る

| 作り直す(表示層) | 触らない(動作ロジック) |
| --- | --- |
| `AppShell` / `OC_Sidebar` / `OC_ChatMessages` / `OC_ChatMessage` / `OC_ChatInput` / `OC_AskUserForm` / `ChatView` / `LoginView` の**テンプレートとスタイル** | `stores/*`(chat / nav / user)、`lib/*` の全モジュール |
| `NavWindow` の**外枠・ヘッダー・トグル**(`useNavWindow` の座標計算ロジックは維持) | `lib/useNavWindow.js` のドラッグ・境界計算 |
| `NavView` の**コントロール群の配置と装い**(どのボタンをどこに置き、どう見せるか) | `NavMap` / `audioManager` / `usePosition` / `geoutils` / `loraBridge` / `offlinePack` / `tiles` / `sse` / `realtime*` |

**「触らない」列のモジュールは、実機で動いている資産である**(ADR-0017 の理由 1 は今も有効)。表示層の作り直しがこれらの**呼び出し方**を変えることはない。

### 3. ガイダンスマップは「フローティング窓のまま刷新」する

ユーザー判断(2026-08-05)。右ドック化・全画面シート化は採らない。**窓という形は維持し、外枠・ヘッダー・トグル・窓内のコントロール配置を作り直す。**

窓の中身については、**地図本体を主役に戻す**ことを設計目標に置く(§4-3 の解消)。常時表示のコントロールを最小限にし、残りは 1 つのメニューに畳む。**旅程(訪問順)は窓の下部に専用の帯として出す** —— 現在それを担っている "Spots List" は地図に重なるカードで、旅程を読む用途に耐えていない。

### 4. Tailwind の `tw-` プレフィックスを廃止する

現行 `tailwind.config.js` は `prefix: 'tw-'` を設定している。**`tw-` を使っているのは `.vue` テンプレート 8 ファイルだけで、その 8 ファイルはすべて本作業で書き直す**(実測: `grep -rn 'tw-' --include=*.js --include=*.html src index.html public` は 0 件)。プレフィックスを外すと参考実装の記述をそのまま検証・移植でき、テンプレートが読める長さになる。

## 理由(なぜ他案でなくこれか)

| 案 | なぜ採らないか |
| --- | --- |
| **A. ADR-0017 を維持し、既存スタイルの中で手直しする** | **既存スタイルそのものが破綻している。**1 画面にダークとライトの 2 テーマが同居し、カードが本文に重なっている。「既存に合わせる」と、合わせる先が壊れている |
| **B. 参考実装を配色ごと丸ごと移植する** | 2 つが同じ見た目になる。**別アプリである**(キャンパス案内 / 鳥海山観光)。ユーザー判断で色相差し替えを採用済み |
| **C【採用】表示層だけ作り直し、動作ロジックは固定する** | ADR-0017 の**切り分けの論理をそのまま裏返して使える。**バックエンドと地図・音声・位置・LoRa を固定し、変えるのは表示層だけにすれば、壊れたときの原因はそこにしかない |
| **D. フロント全体を作り直す(NavView の分割を含む)** | ADR-0017 の理由 2 が今も有効。**`NavView.vue` の正しい分割線は、オフライン動作を実機で通してからでないと引けない。**分割は本 ADR のスコープ外に据え置く |

ADR-0017 のうち**撤回するのは「新しいデザインシステムを導入しない」の 1 行だけ**である。`NavView.vue` の分割見送り、Service Worker の作り直し見送り、リファクタ目的の変更の禁止は**そのまま維持する。**
