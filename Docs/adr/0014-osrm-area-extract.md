# ADR-0014: OSRM の地図データを鳥海山エリアに切り出し、生成をスクリプト化する

- 状態: **決定 (2026-08-01、Phase 2 設計)**
- 日付: 2026-08-01
- 関係: [ADR-0013](0013-leg-route-door-to-door.md)(この地図データで経路を引く)
- 設計・手順: [50_operations/osrm.md](../50_operations/osrm.md)

## 文脈(何が問題か)

**クリーン clone からシステムを起動できない**(NFR-2 違反)。

| 事実(2026-08-01 実測) | |
| --- | --- |
| `backend/worker/data/map/car` | **15 GB** |
| `backend/worker/data/map/foot` | **17 GB** |
| 合計 | **32 GB**(`japan-latest` = 日本全国) |
| Git | `.gitignore` 済み。**作り方はリポジトリのどこにも書かれていない**([22 §8-6](../22_current_issues.md)) |
| 所有者 | 1.0 GB のファイルが **root 所有**で混在 |

対象エリアは鳥海山周辺の **43 地点に固定されている**([00_project.md](../00_project.md))。旅程の起点・終点も 43 件の中から選ばれる([data_model.md §4.5.2](../30_design/data_model.md))。**全国の道路網を載せている理由がない。**

## 決定(何をすると決めたか)

1. **bbox `lon 139.55〜140.60 / lat 38.80〜39.65` に切り出す**(43 地点の外接矩形に各辺 **約 20 km** の余裕)
2. **元データは Geofabrik の `asia/japan/tohoku-latest.osm.pbf`**(全国版を使わない)
3. **切り出しは `osmium extract --strategy=complete_ways`**
4. **手順を `scripts/build_osrm.sh` にする**(取得 → 切り出し → car/foot の extract/partition/customize → 識別子の書き出し)
5. **ビルド識別子 `backend/data/map/BUILD` を作り、Git で追跡する。**値は `app.routes.params.osrm_build` に入る
6. **エリア外の経路は引けないことを仕様として明示する**

## 理由(なぜ他案でなくこれか)

### 1. 再現性が実際に手に入る

32 GB は「手順があっても現実には配れない」規模である。切り出せば **1 GB 未満・生成 10 分程度**になり、`git clone` + スクリプト 1 本という NFR-2 の要求がそのまま満たせる。

### 2. データ更新が現実的な操作になる

全国版は `osrm-extract` だけで数時間かかる。エリア限定なら数分で終わるので、**「OSM が更新されたので作り直す」が普通の操作になる。**作り直せないデータは、いずれ古いまま固定される。

### 3. 余裕 20 km は迂回路のためである

bbox の切り口で道が途切れると OSRM は `NoRoute` を返す。43 地点の外接矩形は 49 km × 37 km で、20 km の余裕は国道 7 号・日本海東北自動車道・鳥海ブルーラインを丸ごと含む。**`--strategy=complete_ways` と組で、境界をまたぐ way が切れないようにする。**

### 4. `BUILD` 識別子は経路キャッシュの正しさに直結する

[ADR-0013](0013-leg-route-door-to-door.md) により経路は `params_hash` で冪等にキャッシュされる。**識別子が無いと、もう存在しない道で引かれた線がパックに焼かれ続ける。**キーに入れておけば、地図を作り直した瞬間に自然に無効化される。

### 5. 採らなかった案

| 案 | 不採用の理由 |
| --- | --- |
| 全国版を持ち続け、手順だけ文書化する | 32 GB は配れない。**手順があっても再現できないなら NFR-2 を満たさない** |
| Geofabrik の県別(秋田・山形)を 2 つ結合 | 県境をまたぐ道の扱いが増える。bbox 1 回のほうが単純で、余裕も自分で決められる |
| 外部の公開 OSRM サーバを使う | オフライン前提の実行環境で外部サービスに依存しない。レート制限とプロファイル(徒歩の山道)も制御できない |
| OSRM をやめて自前のグラフ探索 | 車と徒歩の道路網を自前で持つコストが見合わない。OSRM は現行で動いている |
| CH(`osrm-contract`)に変える | `/table` と MLD の現行構成で足りている。変える理由がない |

## 影響(この決定で生じる制約・やること)

- **エリア外(仙台・東京など)からの経路は引けない。**旅程の起点は 43 地点のいずれかであり、要求上これで足りる。**将来エリアを広げるときは bbox を変えて再ビルドする**(スクリプトの引数 1 つ)
- `scripts/build_osrm.sh` を追加する
- **compose のマウント元を `backend/worker/data/map` → `backend/data/map` に変え、データ名を `chokai` にする。**`--max-table-size 200` を明示し、healthcheck を実際の `/route` 照会にする
- **`.gitignore` を直す**: `backend/data/map/` を無視しつつ `BUILD` は追跡する。**併せて `.env*` に `!.env.example` を足す**(現状 `.env.example` も無視されており、NFR-6 の受け皿が作れない)
- **旧データ(32 GB)は新データの検証が通ってから削除する**(全国版の再生成には数時間かかるため)
- `travel_times` / `spot_approach` の再計算は**明示操作**(`--force`)にする。地図を作り直しても黙って前提が変わらないようにする
