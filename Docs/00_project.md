# プロジェクト概要 — 目的とやりたいこと

- 状態: **承認(2026-07-31)**(2026-07-30 ユーザーフィードバックにより再定義: 粒度を上げ、手段レベルの記述を排除)
- 日付: 2026-07-30 / 承認 2026-07-31

## 目的

鳥海山エリアの観光を対象に、LLM を用いた対話型観光ガイダンスの研究プロトタイプを構築・評価する。

## やりたいこと

**ここに書くのは「何ができるか」だけ。実現手段(アルゴリズム・データ形式・通信方式)は [10_requirements.md](10_requirements.md) 以降の文書で決める。** 現行実装のやり方(ペルソナ分類の方式、状況バリアントの持ち方など)はここでの約束事ではない。

1. **POI 推薦** — ユーザーの好み・プロファイルを元に、POI の推薦ができる
2. **旅程プランニング** — 旅程(周遊計画)の作成・編集ができる
3. **対話形式** — ChatGPT や Gemini のように、1〜2 をユーザーとの対話形式で行える
4. **オフライン環境でのリアルタイム観光案内** — 観光中は Wi-Fi(インターネット)が使えない環境(LoRaWAN)でも、リアルタイム情報(天気・混雑度)を元に観光案内ができる。案内の主媒体は音声ガイド(TTS)とする(2026-07-30 確認)

## 利用シナリオの前提(2フェーズ)

- **計画フェーズ(オンライン)**: 出発前。通常のインターネット接続下で、対話による推薦・プランニングと、現地で必要になるデータの事前取得を行う
- **観光フェーズ(オフライン)**: 現地。インターネット接続なし。端末に届く通信は LoRaWAN の狭帯域ダウンリンクのみ。案内はこの制約下で成立する

## 実験上の割り切り(値は偽物でよいが、経路は本物)

- 天気・混雑度は実データの取得が難しいため、**値はダミーでよい**
- ただし**ダミーデータはサーバー上に置き、サーバー→(LoRaWAN 相当の経路)→端末という実際の配送経路を通して端末に届け、実挙動を再現する**。端末内でのダミー生成や、実験時だけの HTTP 直接取得といったショートカットで挙動を偽らない

## スコープ外(2026-07-30 ユーザー確認済み)

- **多言語対応(en/zh)** — 現行実装は 3 言語対応だが、要求から外す。対話・案内・UI は日本語のみ(設計上、言語追加を不可能にするようなハードコードは避ける)
- **会話の長期記憶**(過去セッション横断のベクトル検索) — 要求から外す。文脈は直近の会話+永続プロファイルで構築する(将来の再導入を設計で妨げない)
- 大規模同時アクセス・商用機能(認証強化・課金など)

## 制約・前提

- 開発者は 1 名(研究者)。運用先は研究室のホスト 1 台
- 生成 LLM はホスト GPU 上の vLLM(OpenAI 互換 API)。別マシンの埋め込みサーバは長期記憶のスコープ外化に伴い不要になる
- 品質特性の優先順位: 変更のしやすさ・実験のしやすさ・再現性 > その他すべて
